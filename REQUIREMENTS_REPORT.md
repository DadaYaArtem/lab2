### 12. Принципы SOLID
- **Требование**: Применение принципов SOLID
- **Реализовано**: **Все 5 принципов**
- **Статус**: ✅ **ВЫПОЛНЕНО**

**S - Single Responsibility Principle:**
- Каждый класс имеет одну ответственность
- `OrderService` - только управление заказами
- `PaymentService` - только обработка платежей
- `DeliveryService` - только доставка
- `Kitchen` - только приготовление
- `Inventory` - только управление запасами

**O - Open/Closed Principle:**
- Система открыта для расширения через наследование
- Новые типы пицц добавляются без изменения базовых классов
- Новые способы оплаты добавляются через наследование `Payment`
- Новые стратегии ценообразования через интерфейс `PriceCalculationStrategy`

**L - Liskov Substitution Principle:**
- Любой `Employee` может быть заменен своим подклассом
- Все подклассы `Payment` работают взаимозаменяемо
- Все `Product` могут использоваться единообразно

**I - Interface Segregation Principle:**
- Интерфейсы разделены по функциональности
- `Cookable` - только для приготовления
- `Payable` - только для оплаты
- `Deliverable` - только для доставки
- Клиенты не зависят от неиспользуемых методов

**D - Dependency Inversion Principle:**
- Зависимость от абстракций, а не конкретных реализаций
- `OrderService` зависит от интерфейса `Cookable`, а не от `Kitchen`
- `PaymentService` использует `PaymentFactory` для создания платежей
- Стратегии ценообразования внедряются через интерфейс

### 13. Паттерны GRASP
- **Требование**: Применение паттернов GRASP
- **Реализовано**: **Все основные паттерны**
- **Статус**: ✅ **ВЫПОЛНЕНО**

**Information Expert:**
- `Order` знает свою цену и управляет своими элементами
- `Product` знает свою цену и доступность
- `LoyaltyCard` управляет своими баллами
- `Inventory` знает о запасах ингредиентов

**Creator:**
- `Pizzeria` создает `Order`, `Menu`, `Kitchen`
- `OrderService` создает заказы для клиентов
- `PizzaFactory` создает различные типы пицц
- `PaymentFactory` создает платежи

**Controller:**
- `Main` - главный контроллер пользовательского интерфейса
- `OrderService` контролирует процесс заказа
- `PaymentService` контролирует платежи
- `DeliveryService` контролирует доставку

**Low Coupling:**
- Классы слабо связаны через интерфейсы
- Использование фабрик уменьшает зависимости
- Сервисные слои изолируют бизнес-логику

**High Cohesion:**
- Каждый класс имеет связанные обязанности
- Методы класса работают с его данными
- Логически связанная функциональность группируется

### 14. Design Patterns (паттерны проектирования)
- **Требование**: Применение паттернов проектирования
- **Реализовано**: **2 основных паттерна + дополнительные**
- **Статус**: ✅ **ВЫПОЛНЕНО**

**Factory Pattern (Фабрика):**

- `IngredientFactory` - создание ингредиентов
- `PaymentFactory` - создание платежных объектов

**Strategy Pattern (Стратегия):**
- `PriceCalculationStrategy` - различные стратегии ценообразования
- `StandardPricingStrategy` - стандартное ценообразование
- `DiscountPricingStrategy` - ценообразование со скидками
- `PremiumPricingStrategy` - премиум ценообразование

**Builder Pattern (Строитель):**
- `CustomPizza` позволяет создавать пиццу с настраиваемыми ингредиентами

**Singleton Pattern (Одиночка):**
